1. Own audio analysis across the XML recut run

cutdeck/xml_recut.py:496–565 · cutdeck/sequence_mixdown.py:96 · transcribe/pipeline/run.py:105–125

Before

Mixdown plan → ingest again

Config copied; denoise policy differs.

After
Recut analysis module
Decode and analyze once per required audio policy
Duration · speech spans · transcript provenance

ASR and cutting share compatible analysis.

Problem: Two ingest passes run without ASR, three with ASR; the XML path honors denoise=true while whole-file ASR disables it.

Solution: Give one deep module ownership of analysis and its policy, retaining distinct variants only when required; keep the XML transformation pure.

  • Locality: preprocessing decisions live together.
  • Leverage: reuse duration and speech spans.
  • Tests cross the complete recut interface.

Deletion test: absorb repeated orchestration into the owner; deleting the owner would scatter policy again. No new adapter needed. Measure speed before claiming a gain; preserve cut geometry and explicitly compare denoise variants.

Verification: deterministic audio fixture, short Thai speech islands, identical cut frames for unchanged policy, and counted decoding passes.

2. Make transcription job ownership explicit

transcribe/pipeline/run.py:55–76, 203 · transcribe/db/store.py:380–414 · cutdeck/xml_recut.py:537–560

Before
Resume: media + engine names + version

After
Transcription job module
Own execution identity
Check cached-result compatibility
Carry exact job provenance to cutting

Problem: Resume matching omits model/decode settings and bias inputs; CutDeck recovers the job separately using a latest-job lookup.

Solution: Deepen job ownership so cache reuse proves compatibility and the completed transcription carries its own provenance, while preserving existing callers.

  • Locality: checkpoint rules stay together.
  • Leverage: exact provenance reaches CutDeck.
  • Tests cover failure then changed configuration.

Deletion test: remove caller-side rediscovery, not the useful pipeline module. Keep the SQLite adapter and SQL ownership. Define fingerprint inputs during design; avoid invalidating expensive decoding for unrelated output settings.

Verification: unchanged retry reuses results; changed checkpoint, cue policy or bias input cannot silently reuse incompatible results; concurrent jobs cannot misassociate the plan.

Problem: Default track selection checks for clips but not track enabled state; source audio placement and rewrite validation are owned separately.

Solution: Establish one seam for validated sequence facts and supported timing, shared by extraction and recut; retain surgical tree mutation.

  • Locality: frame interpretation stays together.

Verification: disabled first track, negative track selection, source ticks, source/sequence rate mismatch, missing references and stacked-track sync; unsupported cases should refuse clearly.

Strong · smallest first patch engine adapters

4. Own engine cleanup on every exit

transcribe/pipeline/engine_run.py:109–145, 164–186

Before
Load → decode → unload
Decode raises → unload skipped

Repeated in normal and resumed paths.

After
Engine execution module
Acquire model
Decode with existing adapter
Always attempt cleanup on exit

Problem: Explicit unload calls follow decoding without a finally bracket, so failures bypass the normal cleanup sequence.

Solution: Deepen the existing execution module with shared residency ownership across normal, Engine B and resumed self-ensemble paths.

  • Locality: cleanup has one owner.
  • Leverage: all adapters gain failure cleanup.
  • Tests inject decode and load failures.

Deletion test: replacing repeated cleanup earns depth; adding a pass-through execution module would not. The existing engine seam already has multiple real adapters. Explicit cleanup is skipped today; persistent VRAM leakage has not been measured.

Verification: cleanup runs after failures, preserves the original exception, and never permits two models resident at once.

Top recommendation

It directly improves the daily XML → transcribe → cut path by removing repeated work and concentrating preprocessing decisions. Engine cleanup is a smaller independent patch if you prefer the narrowest starting point.
