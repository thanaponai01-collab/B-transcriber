# Targeted passage review and personal subtitle layout

Recognition rechecking and display formatting now have separate entry points.
Neither trains a model or imports reference answers into recognition prompts.

## Review a saved transcription

```powershell
.\.venv\Scripts\python.exe -X utf8 -m tools.recheck_subtitles 44 --output output/review-44
```

This selects up to six passages using unfamiliar Thai fragments, low confidence,
short cues, and dense text. These are review signals, not proof of mistakes.
High confidence does not suppress the other signals. Add `--plan-only` to inspect
selection without loading models. Add repeated `--window START:END` arguments
(seconds) to prioritize particular passages, and `--max-windows N` for the budget.
Explicit requests that do not fit the budget fail rather than disappear silently.

Each passage includes whole neighboring captions where they fit within 12 seconds.
Thai Whisper and Qwen receive identical 16kHz audio excerpts. They load sequentially
and unload even after decode failures. They can still segment that audio differently
internally, but their full-passage text is compared over the same input samples.
No cross-model confidence comparison or automatic replacement is performed.

Open the generated `review.html` in a browser, keeping its `audio` folder alongside
it. Listen to a passage, compare alternatives, edit the original captions, and
download the reviewed SRT. All captions outside the review windows remain in the
export. A copyable SRT text box provides a fallback for browsers that block Blob
downloads. Edits are in memory until exported; reopening the page resets them.

The report is a sidecar and does not write corrections to the production DB.
To feed a reviewed SRT back into the existing correction workflow, use
`scripts/learn_from_srt.py` with the corresponding job ID. Added words may require
manual retiming: the review export intentionally preserves original cue timings.
The JSON also records candidate cue timestamps when generated by the new tool;
they are alternatives, not forced-aligned replacements for accepted edits.

## Learn and apply display preferences

```powershell
.\.venv\Scripts\python.exe -X utf8 -m tools.subtitle_layout learn 'output/Short1 mine.srt' 'output/Short2 mine.srt' 'output/Short3 mine.srt' --output output/style.json
.\.venv\Scripts\python.exe -X utf8 -m tools.subtitle_layout apply source.srt --profile output/style.json --output formatted.srt
```

The profile learns a wrap threshold and typical line size from manual captions.
It records reference hashes and descriptive cue-duration statistics, but does not
learn word replacements or impose new timings. Wrapping uses the existing Thai
bound-unit rules, keeps Latin words intact, and preserves existing authored line
breaks. It is a display preference model, not a learned semantic phrase model or
speaker diarization system. Maximum two generated lines; an indivisible long term
may remain longer than the preferred line size.

The normal entry point supports both features:

```powershell
.\.venv\Scripts\python.exe transcribe_file.py clip.mp3 --review-passages --layout-profile output/style.json
```

`scripts/export_job.py --layout-profile output/style.json` also applies the layout
to SRT/VTT exports. Its exports now honor saved editor corrections, matching the
web editor's behavior. Review generation remains opt-in because it loads models
and requires the installed Qwen adapter/dependencies and weights.

## CFD 95 evaluation, 2026-09-18

Four matched passages were tested using the supplied audio. The manual focus
ranges were 38.54–43.42s and 97.30–100.84s; two additional flagged passages were
selected automatically. With context the four windows total 35.40 seconds.
The default automatic six-window plan also flags the missing-speech region,
without consulting the corrected SRT.

Both models recovered `เขาก็ยังเป็นแบบนี้มาตลอดเลย`, missing from the original
39.68–43.42s cue. This demonstrates a useful second-pass recovery, not a claim
that all alternatives are correct. Both still misrecognize the marriage phrase
around 98s, and neighboring words sometimes regress. There is no automatic
selection gate justified by this sample; every suggestion remains for review.

The layout profile was fitted on three older corrected clips: 65 captions,
26 multiline; target line size 16 characters, wrap threshold 26 characters.
CFD 95 was excluded from profile fitting. On its corrected text and cue timings,
the layout-only evaluation finds 20 of 22 multiline cues, adds six extra wraps,
misses two, and matches 59/79 layouts exactly. This is not end-to-end ASR accuracy.
The separately formatted 63-cue machine transcript has 29 multiline captions;
its words and timing remain unchanged.

Artifacts: `output/shorts-targeted-review/review.html`, `review.json`, `audio/`,
`layout-profile.json`, `layout-evaluation.json`, `shorts.layout.srt`.

Validation covers selection without confidence dependence, matched input samples,
sequential engine lifetime, exception cleanup, explicit review budgets, HTML
escaping, subtitle round trips, layout text/timing preservation, and saved
correction export. Browser inspection verified rendering, editing, and generated
SRT text with all 66 original cue timestamps. The in-app browser crashed during
the initial audio-control check and did not report a download event; media files
were independently decoded and their durations verified, and the copyable export
fallback was exercised successfully. Native browser playback/download remains
an environment-specific verification limit.
